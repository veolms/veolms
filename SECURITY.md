# Security policy

## Reporting a vulnerability

Please report suspected security vulnerabilities privately through [GitHub's private vulnerability reporting](https://github.com/veolms/veolms/security/advisories/new). Do not open a public issue or disclose sensitive details publicly before maintainers have had an opportunity to investigate and address the issue.

Include the affected version or commit, a description of the impact, steps to reproduce, and any relevant logs or proof of concept. Remove credentials and personal information from attachments. Maintainers can use the private report to ask follow-up questions and coordinate a fix and disclosure.

If private reporting is unavailable, contact the maintainers privately through the repository's listed community channels without sharing vulnerability details publicly, and ask for a secure reporting method.

## Supported versions

Security fixes are developed for the `dev` branch. Check with the maintainers about support for older versions or deployed releases.
