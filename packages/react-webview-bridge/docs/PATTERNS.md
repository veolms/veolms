## 1. Typed contract

The native build generates `native-bridge-contracts.d.ts` (KSP output, e.g.
`app/build/generated/ksp/<variant>/resources/native-bridge-contracts.d.ts`). Put it into the webapp (copy it, or sync it in CI) and
**do not hand-write** the native API surface when a generated one exists.

Then register it once, in the one place that names it. The contract stays in your app; this package never imports it.

```ts
// src/native/bridge.ts — the one place that names the contract
import type { NativeBridgeContract } from "./native-bridge-contracts"; // generated

declare module "@veolms/react-webview-bridge" {
  interface Register {
    contract: NativeBridgeContract;
  }
}
```

Every generic export now defaults to it, so no hook needs a type argument:

```ts
const platform = useBridgeCall((b) => b.platform()); // b: BridgeInstance<NativeBridgeContract>
const { bridge } = useNativeBridge();
await getBridgeController().call((b) => b.files.info(path)); // typed arguments and result
```

- The file must be part of the app's TypeScript program (inside its `include`). Importing it is not required for types.
- One contract per app. A second endpoint names its own contract as a type argument: `useNativeBridge<PaymentsContract>()`,
  `useBridgeCall((b: BridgeInstance<PaymentsContract>) => b.pay())`. See [§10](#10-multiple-endpoints).
- Without a registration, `T` defaults to `Record<string, unknown>`, as before.

The contract is **compile-time only**. Native metadata from the handshake decides at runtime what exists (see [§8](#8-feature-detection-has-and-noop-null)).
Wire paths are colon-separated: `bridge.systemBars.hideStatusBar()` is sent as `systemBars:hideStatusBar`.

## 2. One provider at the root

```tsx
// src/main.tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import {
  NativeBridgeProvider,
  type NativeBridgeOptions,
} from "@veolms/react-webview-bridge";

// Module-level constants: options are read once ("first call wins"), so never build them inline per render.
const BRIDGE_OPTIONS: NativeBridgeOptions = { timeoutMs: 15000 };
const BRIDGE_RETRY = { maxAttempts: 5, initialDelayMs: 100 } as const;

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <NativeBridgeProvider
      endpointName="NativeBridge"
      options={BRIDGE_OPTIONS}
      retry={BRIDGE_RETRY}
    >
      <App />
    </NativeBridgeProvider>
  </StrictMode>,
);
```

- Put **one** provider per endpoint, as high as possible (above the router), so route changes never unmount it.
- StrictMode is fine. It does not cause a second init or a dispose.
- `endpointName` must equal the name native registers (Android `addWebMessageListener`/`addJavascriptInterface`, iOS
  message handler). The default is `"NativeBridge"`.
- Android modern endpoints only accept the origins native allow-lists (e.g. `http://10.0.2.2:3000` in the test app). A page
  served from another origin sees no endpoint and ends in `unavailable`.

## 3. Gating UI on state

```tsx
import { useNativeBridge } from "@veolms/react-webview-bridge";

export function NativeGate({ children }: { children: React.ReactNode }) {
  const { state, error, attempt, maxAttempts, retry } = useNativeBridge();
  switch (state) {
    case "ready":
      return <>{children}</>;
    case "idle":
    case "initializing":
      return (
        <p>
          Connecting to the app… ({attempt}/{maxAttempts})
        </p>
      );
    case "unavailable":
      return <p>Open this page inside the app to use this feature.</p>; // normal browser
    case "error":
      return (
        <p>
          Native bridge failed: {error?.message}{" "}
          <button onClick={retry}>Retry</button>
        </p>
      );
  }
}
```

Gate only what needs native. The rest of the page should render in every state. `unavailable` is the **normal** state in a
desktop browser or a preview environment, so it is not an error.

## 4. Fire-and-forget vs awaited calls

```tsx
import { useBridgeCall, useNativeBridge } from "@veolms/react-webview-bridge";

function Toolbar() {
  const { call } = useNativeBridge();

  // Fire-and-forget: still attach a catch (call() returns a promise that can reject).
  const toast = (msg: string) =>
    void call((b) => b.showToast(msg)).catch((e: unknown) =>
      console.warn("toast failed", e),
    );

  // Awaited with request state rendered by the component:
  const platform = useBridgeCall((b) => b.platform());

  return (
    <>
      <button onClick={() => toast("Saved")}>Toast</button>
      <button
        onClick={() => void platform.run().catch(() => undefined)}
        disabled={platform.status === "pending"}
      >
        Load platform
      </button>
      {platform.status === "success" && <span>{platform.data?.type}</span>}
      {platform.status === "error" && (
        <span>Failed: {String((platform.error as Error).message)}</span>
      )}
    </>
  );
}
```

- `useBridgeCall` with arguments: `const greet = useBridgeCall((b, name: string) => b.greet(name)); greet.run("Ann")`.
- Inside an async handler where you need the result, just `await call(...)` in `try/catch`.
- `void` results resolve to `undefined` (native `ack`). An explicit `null` stays `null`.
- To bound long native operations, set `options.timeoutMs` (provider level, default 30000). `0` disables it, but then a lost
  reply waits forever.

## 5. Calls before ready

You don't need to wait for ready yourself: `call` and `useBridgeCall.run` **queue** until ready (default up to 10 s).

```tsx
function Analytics() {
  const { call } = useNativeBridge();
  const reported = useRef(false);
  useEffect(() => {
    // StrictMode runs this effect twice; report once.
    if (reported.current) return;
    reported.current = true;
    // Runs on first mount, possibly while state is idle/initializing: queued, then executed once ready.
    void call((b) => b.platform(), { timeoutMs: 20000 })
      .then((p) => report(p.type))
      .catch((e: unknown) => {
        if (
          isBridgeNotReadyError(e) &&
          (e.reason === "unavailable" || e.reason === "disposed")
        )
          return; // expected
        console.warn(e);
      });
  }, [call]);
  return null;
}
```

- Use `{ waitForReady: false }` for optional actions that should be skipped rather than queued. They reject immediately with
  `reason: "not-ready"`.
- Use `{ timeoutMs: 0 }` to wait without a time limit. It still rejects on `unavailable`/`error`/dispose.
- Use `{ signal }` to cancel the wait when a component unmounts:

```tsx
useEffect(() => {
  const ac = new AbortController();
  void call((b) => b.platform(), { signal: ac.signal }).then(
    setPlatform,
    ignoreNotReady,
  );
  return () => ac.abort();
}, [call]);
```

The signal cancels only the **wait for readiness**. Once the native call was sent, it runs to completion.

## 6. Events

```tsx
import { useBridgeEvent } from "@veolms/react-webview-bridge";

function Battery() {
  const [level, setLevel] = useState<number | null>(null);
  // Type null in when native may send no payload.
  useBridgeEvent<{ level: number } | null>("battery", (p) =>
    setLevel(p?.level ?? null),
  );
  return <span>{level ?? "?"}</span>;
}

function Chat({ active }: { active: boolean }) {
  useBridgeEvent<string>("message", (text) => append(text), {
    enabled: active,
  });
  return null;
}
```

- It subscribes once ready, always calls the latest handler, and unsubscribes on unmount, on `eventName`/`enabled` change, and on a new
  session.
- Events are **not buffered**. Anything emitted before the subscription exists is lost. If you need the current value, read it
  with a call or property after subscribing.
- Outside React, or for one-off listeners: `const off = bridge.onEvent<P>("name", handler); … off();`.

## 7. Properties: read, assign, `$get` / `$set`

Generated contracts type a native property as `get x(): Promise<V>` (and `set x(v: V)` if writable, `readonly` otherwise).

```ts
// Read: every property access sends a native `get`. Await it, and do it in a call, not during render.
const tags = await call((b) => b.fix.tags);

// Fire-and-forget assignment: returns immediately; failures go to options.onError (else console.warn).
await call((b) => {
  b.fix.tags = ["a", "b"];
});

// Awaited write: resolves once native acknowledged it, rejects with the real error.
await call((b) => b.$set("fix:tags", ["a", "b"])); // root helper with the full colon path

// Explicit read helper (resolves null when native has no readable property of that name).
const v = await call((b) => b.$get("fix:readOnly"));
```

- The helpers `$get`/`$set`/`$has` exist on every proxy level at runtime, but the generated contract types them only at the
  root (through `BridgeInstance`). The full-path root form shown above (`"ns:prop"`) is the type-safe way.
- Assigning a read-only property throws `BridgeReadOnlyError` **synchronously** (TypeScript `readonly` usually stops it
  first). `$set` on it rejects with the same error.
- **Never read bridge properties during render** (`<span>{String(bridge.fix.tags)}</span>`). Each read is a native round trip
  that returns a promise.

## 8. Feature detection: `$has` and NOOP `null`

A member that is in your contract but **missing from native metadata** (an older app version, a different platform) is a
**NOOP**: calling it resolves `null` and sends nothing to native. Calls therefore don't throw for missing features. They quietly
return `null`, so detect features explicitly:

```ts
const { bridge } = useNativeBridge();
const canHideBars = bridge?.$has("systemBars") ?? false;          // namespace
const canHide = bridge?.$has("systemBars:hideStatusBar") ?? false; // member (full colon path)

{canHide && <button onClick={() => void call((b) => b.systemBars.hideStatusBar())}>Fullscreen</button>}
```

- `$has()` with no argument on the root means "session alive". It is `false` once disposed.
- `$has` is synchronous and reads metadata only, with no native call, so it is fine during render once `bridge` is non-null.
- A non-void function that returns `null` can mean either "native returned null" or "NOOP". Use `$has` when the difference matters.

## 9. Non-React code

The simplest form is the client: one object whose functions you call directly, typed by the registered contract.

```ts
// src/native/native.ts
import { getBridgeClient } from "@veolms/react-webview-bridge";

export const native = getBridgeClient("NativeBridge", { unavailable: "null" });

// anywhere, in or out of React:
const platform = await native.platform(); // PlatformInfo | null (null: not inside the app)
```

For more control (several calls on one proxy, state subscriptions), services, stores, routers, and analytics can share the
same session through the controller:

```ts
// src/native/bridge-service.ts
import {
  getBridgeController,
  isBridgeNotReadyError,
  type NativeBridgeOptions,
} from "@veolms/react-webview-bridge";

// The same options object as the provider: whichever creates the controller first sets them.
export const BRIDGE_OPTIONS: NativeBridgeOptions = { timeoutMs: 15000 };

// Look the controller up on every use. When the last provider unmounts, its controller is dropped
// and a later mount creates a new one, so a reference kept at module level would go stale.
const controller = () =>
  getBridgeController("NativeBridge", {
    options: BRIDGE_OPTIONS,
  });

export async function getPlatformType(): Promise<string | null> {
  try {
    return (await controller().call((b) => b.platform())).type;
  } catch (e) {
    if (isBridgeNotReadyError(e)) return null; // not inside the app / not ready in time
    throw e;
  }
}

// Subscribe to state outside React:
const live = controller();
const unsubscribe = live.subscribe(() =>
  console.debug("bridge state", live.getSnapshot().state),
);
```

- **Initialization starts only after an `acquire()`.** With a mounted provider that already happened. Code that runs without any
  provider (a worker-like module, a non-React page, a test) must own a reference itself:

```ts
const owned = controller();
const release = owned.acquire(); // starts init if idle; the controller lives until release()
// … later, when done (the session is disposed one macrotask after the last release):
release();
```

- With both a provider and module code, the config comes from whoever creates the controller first. Keep one shared constant
  and pass it to both (`<NativeBridgeProvider options={BRIDGE_OPTIONS}>`).

## 10. Multiple endpoints

```tsx
<NativeBridgeProvider endpointName="NativeBridge" options={MAIN_OPTIONS}>
  <NativeBridgeProvider
    endpointName="PaymentsBridge"
    retry={{ maxAttempts: 2 }}
  >
    <App />
  </NativeBridgeProvider>
</NativeBridgeProvider>
```

Hooks read the **nearest** provider. For an outer endpoint inside an inner provider, use its controller directly:

```ts
const main = getBridgeController("NativeBridge"); // typed by the registered contract
const payments = useBridgeController<PaymentsContract>(); // nearest = PaymentsBridge
```

Each name has its own controller, session, state, retry policy and diagnostics. `disposeNativeBridge("PaymentsBridge")`
leaves `NativeBridge` untouched.

## 11. Iframes

An iframe is a separate document with its own module registry, so it needs its **own** provider at its root, and it gets
its own handshake and session.

```tsx
// frame entry
const FRAME_RETRY = { maxAttempts: 1 } as const; // fail fast where the bridge may not exist

export function FrameRoot() {
  return (
    <NativeBridgeProvider
      endpointName="NativeBridge"
      options={{ timeoutMs: 4000 }}
      retry={FRAME_RETRY}
    >
      <FrameContent />
    </NativeBridgeProvider>
  );
}
```

Platform behaviour (verified on device with JSBridge 0.2.0):

- **Android modern** (`addWebMessageListener`): frames whose origin is allow-listed get their own endpoint. Concurrent calls from
  parent and frame are routed to their own document.
- **Android legacy** (`addJavascriptInterface`): async native replies are delivered **only to the main frame**, so the frame's
  handshake times out and the frame ends in `error` (the endpoint object exists, but no reply arrives). Natives that answer legacy
  requests synchronously (the return value of `postMessage`) do work in frames. If a legacy frame needs async calls, proxy them
  through the parent with `window.postMessage`.

## 12. Re-navigation, logout, teardown

- **SPA route changes**: nothing to do, as long as the provider sits above the router.
- **Full page navigation / reload**: the document is gone, and the next page builds a new session. Nothing to do.
- **Explicit teardown of one endpoint** (logout, switching accounts, a native-side reset that invalidates the session):

```ts
import {
  disposeNativeBridge,
  getBridgeController,
} from "@veolms/react-webview-bridge";

disposeNativeBridge("NativeBridge"); // pending waiters reject "disposed", state → idle
getBridgeController("NativeBridge").retry(); // build a fresh session (or remount the provider)
```

- Unmounting the last provider disposes the session one macrotask later. Use `keepAlive` on a provider that may unmount and
  remount (e.g. inside a conditionally rendered layout) to keep the session.
- Never call `bridge.dispose()` or `clearNativeBridgeCache()` directly in app code (see [LIFECYCLE.md](LIFECYCLE.md#disposal-semantics)).

## 13. Testing with the fake native

`src/__tests__/fake-native.ts` is a protocol-v1 test double of the native side. It installs on `window` as an Android **modern**
(`addEventListener` style) or **legacy** (`postMessage` plus a synchronous return) endpoint. It is not part of the public
export. Copy it into your app's test utilities, or add `"./testing": "./src/__tests__/fake-native.ts"` to this package's
`exports` (changing `exports` to an object with `".": "./src/index.ts"`) if several apps need it.

```tsx
import "./dom.ts"; // jsdom globals first, see src/__tests__/dom.ts
import assert from "node:assert/strict";
import { afterEach, it } from "node:test";
import { act, cleanup, render, screen, waitFor } from "@testing-library/react";
import {
  NativeBridgeProvider,
  getNativeBridgeDiagnostics,
  resetNativeBridges,
} from "@veolms/react-webview-bridge";
import { installFakeNative, type FakeNative } from "./fake-native";

let native: FakeNative | null = null;
afterEach(() => {
  cleanup();
  resetNativeBridges(); // controllers + library cache + counters
  native?.uninstall();
  native = null;
});

it("shows the platform", async () => {
  native = installFakeNative({
    mode: "modern",
    capabilities: [{ path: "platform", kind: "function" }],
    handlers: { platform: () => ({ type: "ANDROID", sdkVersion: 34 }) },
    replyDelayMs: 5,
  });
  render(
    <NativeBridgeProvider retry={{ maxAttempts: 2, initialDelayMs: 5 }}>
      <PlatformLabel />
    </NativeBridgeProvider>,
  );
  await waitFor(() => screen.getByText("ANDROID"));
  assert.equal(getNativeBridgeDiagnostics().buildCalls, 1);
  act(() => native!.emit("battery", { level: 80 }));
});
```

Fake options: `name`, `mode` (`"modern"`/`"legacy"`), `capabilities` (protocol paths and kinds), `handlers` (by path; return
`undefined` for a void `ack`, throw for an error reply), `properties`, `init` (`"ok"`, `"bad-version"` → `error` state,
`"error"`, `"silent"` → handshake timeout), and `replyDelayMs` (legacy with `0` answers synchronously). It records `requests`,
`initCount`, `invokeCount` and `listenerCount`, and has `emit(name, payload)` and `uninstall()`.

Tips:

- Use a small retry policy in tests (`{ maxAttempts: 2-3, initialDelayMs: 5 }`) so terminal states arrive fast.
- Test "not inside the app" by installing **no** fake. The provider then ends in `unavailable`.
- Runner: `node:test` with a jsdom window (`src/__tests__/dom.ts`). The tests in this package (`src/__tests__/`) cover StrictMode single-init, deferred dispose,
  keepAlive, queued calls, timeouts, `unavailable`/`error`, retry, events, NOOP and dispose/re-init. Use them as examples.
